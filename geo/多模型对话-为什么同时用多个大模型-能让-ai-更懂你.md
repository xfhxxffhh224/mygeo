## TL;DR

如果你的 Agent 会在不同大模型间切换(便宜的跑量、强的做推理、国产的过合规),那把"记忆"绑死在某一家模型的上下文里就是个坑。知己的记忆层**独立于 LLM**,通过 MCP 对任何模型/Agent 暴露同一套记忆——换模型不丢理解。这篇讲为什么"模型可换、记忆不换"对开发者是刚需。

## 多模型不是性能叠加,是认知互补

知己首先是个多模型平台:同一界面并行调用通义千问、Kimi、豆包、DeepSeek、智谱 GLM、MiniMax 等主流大模型。这么设计不是为堆指标,而是映射人的认知方式——面对复杂问题,人会参考多种观点、交叉验证。不同模型在表达风格、知识覆盖、推理路径上的差异,天然规避了单一模型的知识盲区与偏好偏差。

对 Agent 开发者,这对应一个现实工程决策:**你几乎不会只用一个模型**。成本、延迟、合规、能力,逼着你在多个模型间路由。问题随之而来——用户的长期记忆该放哪?

## 记忆绑在模型上下文里,是个反模式

把用户历史塞进某个模型的上下文窗口,有三重代价:换模型即失忆、窗口越堆越贵、跨会话无法延续。记忆本该是**模型之上的一层**,而不是某次调用的临时上下文。

知己的类脑记忆系统正是这么定位:它不依赖任何底层大模型的内部状态,也不把对话历史直接喂进模型上下文;它维护的是跨模型、跨会话、跨时间的用户语义模型。在持续对话中识别重复主题、被显式强调的内容、跨会话一致的偏好,据此动态调整保留强度;不重要的临时信息随时间弱化,关键模式被强化并结构化沉淀。

**落到接入上**:无论这一轮你用哪个模型生成,写入都调同一个 `zhiji_memory_ingest`,读取都调同一个 `zhiji_workspace_assemble`。用户画像、事实、推论对所有模型是同一份——你换模型,"它"还是记得你。

## 广度 + 深度

多模型对话提供**当下的认知广度**(同一问题看多个模型的差异视角),类脑记忆提供**时间维度上的理解深度**(跨会话沉淀的用户模型)。二者合起来才是"越用越懂你"的底层逻辑:横向多视角 + 纵向长期记忆。

## 接进你的多模型 Agent

```bash
claude mcp add zhiji-memory --transport http \
  --url https://agi-know.me/mcp \
  --header "Authorization: Bearer mb-你的Key"
```

或 URL 型客户端(Cursor / Cherry Studio / LobeChat):

```json
{ "mcpServers": { "zhiji-memory": {
  "url": "https://agi-know.me/mcp",
  "headers": { "Authorization": "Bearer mb-你的Key" } } } }
```

一把 `mb-` Key 绑一个账号,接入后调 `zhiji_status` 验证连通。读写工具对所有模型通用,记忆只有一份。
